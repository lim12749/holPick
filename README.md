# holPick

서울 경마 경주의 출전마 정보를 분석해 **경주 결과 예측에 도움이 되는 정보를 제공하는 웹 서비스**입니다.

한국마사회가 공공데이터포털을 통해 공개하는 경주마·기수·조교사·경주기록·배당률 데이터를 수집·정규화하고, 이를 조합한 지표와 시각화를 통해 "이 경주에서 어떤 말이 유리한가"를 판단할 근거를 제시하는 것을 목표로 합니다.

> **현재 상태:** 데이터 수집·통계 집계·복승식 예측·시간분할 백테스트까지 동작합니다.
> 예측 성능은 아래 [검증](#검증-어떻게-믿을-수-있는지)에 적은 대로 **시장(배당 인기순)을 아직 넘지 못했습니다.**

---

## 구현된 기능

| 영역 | 내용 |
|---|---|
| 출전표 | 경주일자·경주번호별 출전마 목록, 부담중량·마번·기수·조교사 |
| 경주마 프로필 | 통산/최근 1년 성적, 착순 분포, 레이팅, 산지·성별·연령 |
| 통계 집계 | 기수·조교사·거리·부담중량·휴양일수별 복승 적중률 (축소추정 적용) |
| 각질 분석 | 초반 1F 통과순위로 선행/선입/중위/추입 판정, 경주별 페이스 밴드 |
| 복승 예측 | 8개 요인을 경주 내에서 정규화해 2착 이내 확률 추정 |
| 복승 조합 | Harville 모델로 두 마리 조합 확률과 본전 배당 산출 |
| 검증 | 시간분할 백테스트 + 기준선 대비 대응비교(z값) |

## 이 프로젝트에서 가장 신경 쓴 것

경마 예측은 **틀렸는데 맞은 것처럼 보이기 아주 쉬운 문제**입니다. 그래서 예측 정확도를
올리는 것보다 "이 숫자를 믿어도 되는가"를 담보하는 데 대부분의 시간을 썼습니다.

**누수 차단.** 예측 입력에는 결과를 알아야만 나오는 값(`ord`·`rcTime`·`diffUnit`)을
넣지 않습니다. 각질도 마찬가지입니다 — 그 경주에서의 실제 초반 위치를 쓰면 사후 정보이므로,
경주일 순으로 순회하며 **그 경주 이전 이력만으로 만든 시점별 스냅샷**을 씁니다.
실측 신호는 줄지만(선행 35.7% vs 추입 10.8% → 과거 성향만으로 27.5% vs 12.9%) 이게 정직한 수치입니다.

**축소추정.** 3전 2착인 기수를 66%로 두면 예측이 그 기수에 끌려갑니다. 표본이 작은 항목은
`(적중 + k·기저율) / (출주 + k)` 로 기저율(19.6%) 쪽으로 당깁니다.

**시간 분할.** 앞 기간으로 통계를 만들고 뒤 기간을 맞힙니다. 무작위 분할은 미래 정보로 과거를
맞히는 꼴이라 성능이 허수로 부풀려집니다.

**표준오차와 유의성 검정.** 검증 경주가 100여 개뿐이라 "이겼다"는 말은 이 값 없이는 과장입니다.
같은 경주를 여러 방식이 함께 맞히므로 **대응 비교(paired)** 로 z값을 냅니다. 독립 가정으로
계산하면 표준오차가 과대평가되어 실제 차이를 놓칩니다.

**틀린 판단을 기록으로 남깁니다.** 예를 들어 초기에는 "미시행 경주의 단승배당은 쓰레기값"이라며
배당을 입력에서 뺐는데, 실제로는 미시행 행에도 배당이 실려 오고 오버라운드도 시행 완료 경주와
같은 밴드였습니다. 배당 인기순이 자체 8개 요인보다 정확했고(상위 2두 적중 0.95 vs 0.80),
가장 강한 예측 변수를 이유 없이 버리고 있었던 겁니다. 이런 정정은 지우지 않고 코드 주석에 남깁니다.

## 검증 — 어떻게 믿을 수 있는지

`/analysis/backtest` 화면이 매번 아래를 계산해서 보여줍니다.

- 모델 / 배당 제외 모델 / 레이팅만 / 각질만 / **확정배당 인기순** 각각의 상위 2두 적중 평균 ± 표준오차
- 각 기준선 대비 대응비교 z값 — `|z| ≥ 1.96` 이면 우연으로 보기 어려움
- Brier score, log loss, 1순위 복승 조합 적중률

**배당 인기순이 1차 목표선입니다.** 확정배당은 발매 마감 시점의 시장 컨센서스라 경주 전에
알 수 있는 값이고, 넘을 수 없는 상한이 아니라 넘어야 하는 선입니다. 현재는 넘지 못했습니다.

### API 호출 규격

- **Base URL:** `https://apis.data.go.kr/B551015/{오퍼레이션명}`
  - 예) 경주마 상세정보 → `https://apis.data.go.kr/B551015/API8_2/raceHorseInfo_2` ✅ 검증됨
  - 오퍼레이션명은 데이터셋마다 다르고 명명 규칙이 없습니다. **마이페이지 → 데이터활용 → Open API → 개발계정 → 해당 API → 상세기능**의 요청주소에서 확인하세요.
  - 인증키 없이 경로 존재 여부만 확인하려면 `scripts/probe-endpoints.mjs` 를 쓰면 됩니다.
- **공통 파라미터**
  - `serviceKey` — 발급받은 인증키 (필수)
  - `meet` — 경마장 구분: `1` 서울 / `2` 부산경남 / `3` 제주 *(이 프로젝트는 서울=`1` 중심)*
  - `_type` — `json` 또는 `xml`
  - `pageNo`, `numOfRows` — 페이징
  - 출전표 계열은 경주월·경주일 파라미터를 추가로 받으며, 생략 시 최근 1개월 데이터를 반환합니다.
- **활용신청:** 개발단계는 자동승인, 운영단계는 심의승인. 활용사례 등록 시 트래픽 상향 가능.

### 인증키 설정

1. [공공데이터포털](https://www.data.go.kr)에서 회원가입 후 위 데이터셋들의 **활용신청**을 진행합니다.
2. 마이페이지에서 발급된 **일반 인증키(Encoding/Decoding)** 를 확인합니다.
3. 프로젝트 루트에 `.env.local` 파일을 만들고 아래처럼 넣습니다.

```bash
# .env.local  (git에 커밋되지 않습니다)
KRA_API_KEY=발급받은_Decoding_인증키
KRA_API_BASE_URL=https://apis.data.go.kr/B551015
```

> 인증키는 **서버 사이드에서만** 사용하세요. `NEXT_PUBLIC_` 접두사를 붙이면 브라우저 번들에 노출됩니다. API 호출은 Route Handler(`src/app/api/**`)나 Server Component에서 처리하는 것을 전제로 합니다.

## 프로젝트 구조

```
holPick/
├── src/
│   ├── app/            # App Router — 페이지, 레이아웃
│   │   ├── races/      # 경주일 · 출전표 · 예측
│   │   ├── horses/     # 경주마 목록 · 상세
│   │   ├── analysis/   # 통계 집계 + backtest/ 검증
│   │   ├── datasets/   # 범용 데이터 탐색
│   │   └── diagnostics/
│   ├── components/     # 표, 페이지네이션, 헤더
│   └── lib/kra/        # 도메인 로직 (아래)
├── scripts/            # 엔드포인트 탐색 · 응답 필드 확인
└── next.config.ts      # Turbopack root 고정 설정 포함
```

`src/lib/kra/` 가 이 프로젝트의 본체입니다.

| 파일 | 역할 |
|---|---|
| `client.ts` | 공공데이터 API 클라이언트 — 인증키 마스킹, 오류코드 매핑 |
| `cache.ts` | 디스크 캐시 — 서버 재시작·재배포에도 유지 (일일 호출 한도 3,000 대응) |
| `stats.ts` | 항목별 집계 + 축소추정 |
| `style.ts` | 각질 판정, 시점별 스냅샷(누수 차단), 페이스 밴드 |
| `sectional.ts` | 구간 기록 기반 속도 밴드 |
| `predict.ts` | 복승 확률 추정 — 경주 내 정규화 + softmax |
| `quinella.ts` | Harville 모델 조합 확률, 본전 배당 |
| `backtest.ts` | 시간분할 백테스트, 대응비교 유의성 검정 |
| `dividend.ts` | 배당률 적재, 환급률 |

`@/*` 임포트 별칭이 `src/*` 를 가리킵니다.

## 고지사항

- 이 서비스가 제공하는 분석과 예측은 **공개 데이터에 기반한 참고 정보**이며, 경주 결과를 보장하지 않습니다.
